# 인증 흐름

## 현재 결론

현재 작업 트리에는 사용자 인증 흐름이 구현되어 있지 않다. 인증 SDK 의존성, 로그인·로그아웃 화면, 토큰, 세션, 쿠키, 사용자 저장소, 라우트 가드가 검색되지 않았다. Firebase 관련 파일은 Hosting 설정이며 Firebase Auth 설정은 아니다.

랜딩 페이지는 다음 내용을 명시한다.

- 회원가입 없이 무료 체험
- 회원가입 없음
- 결제정보 없음

따라서 현재 확인 가능한 흐름은 인증이 아니라 익명 체험 흐름이다.

```text
익명 방문자
  -> 랜딩
  -> /experience 입력
  -> /api/try/search 요청
  -> 추천 결과
  -> /result/:companyId 상세 분석
  -> /apply 콜드메일 신청
```

## 접근 제어 상태

모든 프런트엔드 라우트에는 인증 가드가 없다. `createBrowserRouter`가 경로에 따라 컴포넌트를 바로 렌더링한다. `/api/try/search` 개발 미들웨어에도 사용자 인증 또는 권한 확인이 없다.

## 사용자 정보 처리

- 체험 검색 입력은 React 컴포넌트 상태에만 유지된다.
- 코드에는 검색 입력을 localStorage, 쿠키 또는 사용자 계정에 저장하는 로직이 없다.
- 콜드메일 신청은 이메일, 회사명, 제품 정보와 정보 처리 동의를 받는다.
- 개발 환경의 신청은 서버로 전송하지 않고 메모리에서 성공 응답을 만든다.
- 운영 환경의 신청은 백엔드가 연결되지 않아 오류 처리된다.

## 인증과 혼동하기 쉬운 항목

- `UserType`은 로그인 사용자 유형이 아니라 분석 목적 역할(`sales`, `recruiter`, `investor`)이다.
- 콜드메일 신청의 이메일 입력은 계정 생성이나 본인 인증이 아니다.
- `.firebaserc`, `firebase.json`은 현재 정적 Hosting 프로젝트와 SPA rewrite만 정의한다.

## 확인 필요

실제 인터뷰 답변이 제공되지 않아 다음 사항은 확정할 수 없다.

1. 향후 로그인 또는 조직 계정이 필요한지
2. 익명 무료 체험과 인증 후 기능의 경계가 있는지
3. 인증 공급자로 Firebase Auth 또는 다른 서비스를 사용할 계획인지
4. 콜드메일 신청자의 이메일을 어디에 저장하고 누가 접근하는지
5. 운영 API에 인증·요청 제한·감사 로그가 필요한지

인증을 추가하기 전에는 위 항목을 제품·보안 담당자에게 확인해야 한다. 현재 코드만으로 인증 규칙을 새로 만들면 안 된다.
