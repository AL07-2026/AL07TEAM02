# 프로젝트 컨텍스트

## 문서 기준

이 문서는 현재 작업 트리의 코드, `package.json`, `README.md`, 설정 파일을 기준으로 작성했다. 요청에 포함된 인터뷰 답변 영역에는 실제 답변 대신 `[여기에 기존 작업자 답변 붙여넣기]`라는 자리표시자만 있었다. 따라서 인터뷰 답변에서 확정할 수 있는 제품 규칙이나 운영 규칙은 없다.

## 제품 개요

화면에서 사용하는 제품명은 **세일즈 시그널(Sales Signal)** 또는 일부 내부 화면의 **Signal Radar**다. 공개 채용공고를 기업 변화의 신호로 분석해 우선 검토할 기업, 추천 근거, 접촉 대상과 콜드메일 소구점을 보여주는 React SPA다.

현재 코드에서 확인되는 대상 역할은 다음 세 가지다.

- `sales`: 구매 가능성이 높은 기업을 찾는 영업 담당자
- `recruiter`: 채용 수요가 커지는 기업을 찾는 채용 담당자
- `investor`: 성장 신호가 보이는 기업을 찾는 투자 담당자

서비스는 채용정보 기반 추정과 실제 구매 의도를 구분한다고 랜딩 화면에 명시한다.

## 현재 구현 범위

- 랜딩 페이지와 데모 분석 모달
- 역할·검색 목적·지역을 받는 무료 체험 폼
- 채용공고 검색 API와 기업별 추천 분석
- 추천 기업 목록과 상세 분석 화면
- 상세 분석에서 콜드메일 신청 화면으로 대상 기업 전달
- 개발 환경의 콜드메일 신청 Mock 완료 상태
- ALIO·Jooble 수집, Saramin·공통 형식 가져오기, SQLite 저장과 스냅샷
- TypeScript, ESLint, Vitest, Vite 빌드 검증
- Firebase Hosting용 정적 SPA 설정

## 현재 구현하지 않았거나 연결되지 않은 범위

- 회원가입, 로그인, 로그아웃, 세션, 권한 검사
- 운영 환경의 콜드메일 신청 백엔드 저장·전송
- Firebase Hosting에서 `/api/try/search`를 처리할 운영 백엔드
- 브라우저 새로고침 뒤 체험 검색 결과 상태를 복원하는 영속화

## 데이터와 외부 연동

- 기본 로컬 DB: `data/job-signals.db`
- 원본 보관: `data/raw/<source>/`
- CLI 분석 결과 기본 위치: `data/latest-analysis.json`
- 외부 수집 코드: ALIO, Jooble
- 가져오기 어댑터: ALIO, Jooble, Saramin, normalized
- 개발 검색 엔드포인트: `POST /api/try/search` (`vite.config.ts`의 Vite 개발 서버 미들웨어)

`data`의 DB, 분석 결과, 원본 응답은 `.gitignore` 대상이다. 실제 데이터나 API 키를 문서에 복사하지 않는다.

## 인터뷰 답변 반영 상태

반영 가능한 실제 인터뷰 문장이 제공되지 않았다. 다음 내용을 확보하면 이 문서를 갱신해야 한다.

- 제품의 공식 명칭과 핵심 사용자
- MVP 완료 기준과 현재 단계
- 운영 배포 방식과 담당 서비스
- 실제 데이터 소스 및 갱신 정책
- 인증 도입 계획
- 콜드메일 신청의 저장·전송 정책

## 확인 필요

1. `package.json`의 이름·설명은 `react-spa-boilerplate`와 React SPA 보일러플레이트지만 실제 UI는 세일즈 시그널 제품이다. 패키지 메타데이터를 의도적으로 유지하는지 확인이 필요하다.
2. `README.md`는 사람인·ALIO·공통 형식을 설명하지만 현재 파이프라인 코드에는 Jooble도 포함된다. 공식 지원 데이터 소스 목록을 확인해야 한다.
3. `.env.example`에는 `VITE_APP_NAME`, `VITE_API_BASE_URL`만 있지만 서버 코드는 `ALIO_API_KEY`, `JOOBLE_API_KEY`, `JOB_ANALYSIS_QUERY`, `JOB_ANALYSIS_SECONDARY`를 읽는다. 환경변수 문서의 기준을 확인해야 한다.
4. Firebase 설정은 `dist` 정적 호스팅만 구성한다. 개발 서버 미들웨어인 검색 API를 운영에서 무엇으로 대체할지 확인해야 한다.
5. 화면은 회원가입 없는 체험을 명시하고 실제 인증 코드도 없다. 향후 인증이 필요한 제품인지 확인해야 한다.
6. 운영 환경의 콜드메일 신청은 명시적으로 실패하도록 구현되어 있다. 실제 접수 백엔드와 개인정보 처리 방식을 확인해야 한다.
